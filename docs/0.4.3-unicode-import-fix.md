# Windows Modrinth import repair

Reported failure: an already downloaded pack cannot open its Modrinth installer,
with `invalid unicode code point at line 1 column 28`. The reported Windows
account contains accented characters.

The former handoff read Modrinth's registered executable through Windows
PowerShell's locale-dependent stdout and parsed those bytes as UTF-8 JSON.
Version 0.4.3 reads the registration with `RegGetValueW`, keeps the command as
UTF-16, parses it with `CommandLineToArgvW`, and starts the executable with the
archive as a separate argument. It never evaluates the registry command as shell
code. REG_EXPAND_SZ registrations are expanded by Windows. No codepage or user
directory change is necessary.

A downloaded `.mrpack` stays reusable after a failed handoff. Both applications
also offer **Open downloaded pack folder** for manual import. The UI explains
that no pre-existing Modrinth profile is needed. Modrinth still performs the
installation and registers the independent profile after the user confirms it;
the updater never writes Modrinth's profile database.

Regression coverage:

- Actual disposable HKCU registry read containing `Jan Božac`, with cleanup.
- UTF-16 executable parsing with Croatian letters, spaces and supplementary
  Unicode characters.
- Empty Modrinth database, new pack population, verified local archive export,
  Minecraft/Fabric dependencies, included mod and independent-profile marker,
  pending archive reuse, and unchanged Modrinth database. All test paths are
  disposable and include accented characters.

Publication is a separate authorized operation. Source changes or a local build
do not update an installed application or the GitHub release automatically.
