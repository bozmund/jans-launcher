# Updater application version and updates

The Modpack Updater now displays **App version 0.4.4** at the top, separately
from the installed modpack version. **Check for app updates** is always visible.
The app also performs a read-only release check when its window opens.

When a newer release is available, **Update app to …** verifies its SHA256SUMS,
replaces this application and restarts it. The updater explicitly selects the
`jans-modpack-updater` release asset on Windows/Linux, regardless of the name the
downloaded executable was saved under. It cannot accidentally turn into the
standalone launcher. Missing release assets and network failures are shown as
retryable errors, rather than being reported as “up to date”.

Before replacing the app, the background worker is asked to finish and exit.
An active modpack transaction is never forcibly interrupted. If that worker
does not finish within the bound, the app update is deferred with an error;
the current executable and player files remain intact. A failed app download
restarts a worker that was stopped. On restart, an enabled enrollment starts
the current version's worker and refreshes its login startup entry.

Tests cover product/platform-specific release selection, missing assets, real
HTTP download/checksum success and corruption rejection, graceful worker
completion, timeout without data changes, and asynchronous app-check results
not clearing the busy flag of an active pack update.

Versions through 0.4.3 do not have this updater button. Users need to download
0.4.4 once; subsequent application updates can be installed from this window.
Modpack updating and its existing configuration-preservation policy are unchanged.
