# Plan: jans-launcher (accepted 2026-11-03)

Rust modpack updater + launcher for Jan's Fabric 26.3 pack, replacing Modrinth shared-instance
updates (500 MB limit). License MIT. README in English, app UI Croatian + English.

## Decisions from the interview

| Topic | Decision |
|---|---|
| Interface | GUI only for friends (egui); a hidden `publish` CLI subcommand for Jan |
| Pack hosting | Git repo holds a manifest + changelog + small overrides; Modrinth mods from Modrinth CDN; Jan's own jars from GitHub Release assets |
| Launch | Full own launcher (Java, Minecraft, Fabric, Microsoft login) |
| MS login | Real device-code login; Jan registers an Azure app and applies for Mojang approval. Until approved: fallback syncs a chosen Modrinth/Prism profile and opens Modrinth App |
| Java / Fabric | Fully automatic (Mojang Java runtime, Fabric loader version from manifest), RAM setting |
| Fetch view | Like Modrinth: changelog text, added / removed / updated (old -> new version), download size |
| User files | Configs are copied only if missing ("once"); app touches only files it installed; saves, options.txt, servers.dat, user's extra mods never touched |
| Self-update | Automatic from GitHub Releases (verify SHA256, replace exe, restart) |
| Name | `jans-launcher` |
| Publishing | `jans-launcher publish` command run on mony |

## Repositories

- `jans-launcher`: app code, GitHub Actions building `jans-launcher.exe` (Windows x86_64) and
  `jans-launcher` (Linux x86_64 tar.gz) + SHA256SUMS on `v*` tags.
- `jans-modpack` (pack repo): `pack.json`, `CHANGELOG.md`, `overrides/`. One commit = one pack version.
  Jars are never committed.

## Manifest (`pack.json`)

Pack version, Minecraft `26.3`, Fabric loader version, and per file: path, sha512, size, download URL,
display name, version label, policy (`managed` = always synced, `once` = only if missing).
URLs: Modrinth CDN (resolved by hash via Modrinth API), GitHub Release asset for own jars
(uploaded once per unique hash), `raw.githubusercontent.com/<owner>/<repo>/<commit>/overrides/...`
for overrides (pinned to commit).

## GUI

- Check for changes: changelog per new version, content diff, total download size.
- Update: parallel downloads, sha512 verify, atomic writes; only files the app installed are
  changed; removed mods go to `.jans-launcher/trash/<date>`.
- Play: own launcher (Mojang Java runtime, client, libraries, assets, Fabric), RAM setting.
- Microsoft device-code login; `docs/MICROSOFT_LOGIN.md` explains Azure app + Mojang approval.
  Fallback: instance folder can point at an existing Modrinth/Prism profile; button opens Modrinth App.
- One-time import from a Modrinth profile (saves, options.txt, servers.dat).
- Self-update from GitHub Releases.

## `jans-launcher publish`

Reads Jan's profile, includes folders listed in `publish.toml` (mods, config, defaultconfigs,
shaderpacks, resourcepacks, global_packs), skips `*.bak*` / `*.disabled`, classifies jars via
Modrinth API, uploads new own jars with `gh`, writes `pack.json`, appends changelog, prints the git
commands. Never pushes by itself.

## Distribution

Windows: portable `.exe` (unsigned, SmartScreen warning). Linux: tar.gz with binary + `.desktop`.
`flake.nix` for NixOS.

## Testing

Local end-to-end only, nothing published: publish from the Windows profile (read-only) into a local
test pack with local assets; install into a temp instance and verify hashes; simulate a new version
(remove / add / update mod, changed config) and verify diff + user files untouched; launch Minecraft
in an offline test mode to reach the main menu. Linux build via GitHub Actions (after Jan approves a
push) or locally on mony in a separate folder.
